# Boomkin identity

Fresh Hermes onboarding creates the Boomkin SOUL and instructions from [src/core.ts](../src/core.ts). Existing user files are preserved. Use infrastructure and data skills to establish available tools and evidence, then load only the primitive or venue workflow needed for the task.

The identity routes lending, staking, yield, tokenized assets, swaps/bridges, derivatives, payments and governance alongside LP and Hyperliquid. Portfolio reconciles holdings and performance; security investigates token risks and evidence changes, and reviews exact transaction effects and continuing authority. These are optional installed capabilities, not instructions to invoke every pack.

Boomkin runs on native Hermes, preserving its model, memory, tools and scheduling behavior. Skills provide procedures and evidence handoffs; account access and financial authority remain explicit. The name is a nod to the moonkin meme. See [workflow examples](WORKFLOWS.md).
